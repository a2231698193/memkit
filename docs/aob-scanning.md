# AOB 特征码扫描：不用调试器找偏移

## 结论

**偏移可以自动找。** 不需要人肉在 x64dbg/Cheat Engine 里下断点、看寄存器、记偏移。

方法：**AOB 特征码扫描**（Array of Bytes pattern scanning）。

这是**通用能力**，适用于任何 x86-64 原生程序，不限于某个游戏。

---

## 原理

程序每次更新后数据地址会变（ASLR + 重编译），但**访问数据的代码不会大变**。

而访问数据的代码里有一条固定结构的指令：

```
48 8B 05 ?? ?? ?? ??     mov rax, [rip + disp32]
^^^^^^^^^^^ 固定 3 字节    ^^^^^^ 这 4 字节的 disp 就是"数据 - 指令末尾"
```

所以：

```
1. 在代码段搜 "48 8B 05 ?? ?? ?? ??"
2. 命中后，读 disp32（4 字节有符号）
3. target = 命中地址 + 7 + disp32
4. target 就是数据地址（静态偏移）
```

全程程序自己算，不需要人眼。

**这是编译器产物，不是游戏特性。** 任何 ×86-64 程序里，
`mov reg, [rip+disp32]` / `lea reg, [rip+disp32]` 都是最常见的数据引用方式。

---

## 为什么比人工找稳

| | 人工找 | 扫描 |
|---|---|---|
| 更新后 | 看到"还是这条指令但 disp 变了" → 必须重新找 | 指令字节没变 → 扫到同一位置 → 重算 disp → **自动得到新地址** |
| 耗时 | 几分钟到几小时 | 毫秒 |
| 出错 | 手抄偏移错一位就废 | 无人工环节 |
| 版本兼容 | 每个版本都要重做 | 只有**指令本身被改掉**才要更新特征码 |

关键洞察：**特征码描述的是代码，不是数据。代码比数据稳定得多。**

## 实现：`src/os/scanpattern.hpp`

### 1. 特征码解析

支持三种写法：

```
"48 8B 05 ?? ?? ?? ??"     ← 空格分隔，?? = 一字节通配
"488B05????????"           ← 紧凑
"0x48 0x8B 0x05 ? ? ? ?"   ← 0x 前缀，单问号
```

全部解析成同样的 `bytes[] + mask[]`：

```
bytes = 48 8B 05 00 00 00 00
mask  =  1  1  1  0  0  0  0     (1 = 必须匹配)
```

**`??` 是一字节，不是两字节。** 这是最容易写错的地方——第一版写成"每个 `?` 产生一个字节"，导致 `?? ?? ?? ??` 变成 8 字节而不是 4 字节，整个模式错位。

正确逻辑：吃掉 1 或 2 个 `?`，只产生 1 个通配字节。

### 2. 扫描

分块读（默认 1MB），块间留 `pattern_size - 1` 的重叠，防止跨块匹配被漏掉。

**遇到不可读页时退化成 4KB 粒度重试**，而不是整块跳过。这是第二个坑——模块尾部那块跨到不可读页，整块 1MB 都没被扫描，表现为"扫描 0 命中"。

### 3. RIP 相对解析

```cpp
uintptr_t resolve_rip_relative(session, hitAddr, wildcardOffset, 4);
// target = hitAddr + wildcardOffset + 4 + disp32
```

为什么是 `wildcardOffset + 4` 而不是 `wildcardOffset + 7`：

`rip` 指向**下一条指令**。对 `48 8B 05 [disp32]` 来说，disp 在 index 3，指令总长 7 = `3 + 4`。所以 `rip = hit + 3 + 4`。

### 4. 唯一性判据（最重要）

```cpp
if (hits.size() > 1) return r;   // 不唯一 = 拒绝
```

**不唯一的特征码比找不到更危险。**

- 找不到 → 报错，知道出问题了
- 找错 → 静默用错数据，表现为"血量读到 0xCCCCCCCC"这类诡异 bug

所以 `resolve()` 在命中多个时直接返回失败，并报告 `matches` 数量，让调用方能诊断"是不是特征码太短了"。

## 实测

对自身模块（365KB）实测：

```
--- 特征码解析 ---
[ OK ] 48 8B 05 + 4 通配 = 7 字节
[ OK ] 首个通配在 index 3
[ OK ] 紧凑写法也是 7 字节
[ OK ] 单问号也是 7 字节
[ OK ] 0x 前缀不影响长度
[ OK ] 全通配被拒绝（没有固定字节）

--- 特征码扫描 ---
[ OK ] MZ 在模块开头
[ OK ] PE 签名位置正确
[ OK ] 48 8B 05 ?? ?? ?? ?? 命中 16 处

--- 特征码解析到地址 ---
[ OK ] PE 签名命中 base+0x80
[ OK ] 不唯一模式被拒绝（ok=false，matches=2）

--- RIP 相对寻址 ---
[ OK ] 5/5 个 lea 解析出可读地址
```

`lea rcx,[rip+x]` 解析出的地址全部可读 —— 说明 disp 计算正确。

## 用法

```cpp
#include "os/scanpattern.hpp"

os::Session s;
s.Begin(pid);

uintptr_t modBase = os::module_base(pid, L"Game.exe");
size_t modSize = /* 模块大小 */;

// 一步到位：给特征码，拿数据地址
auto r = scan::resolve(s, modBase, modSize,
                       "48 8B 05 ?? ?? ?? ?? 33 DB 45 8B E1");
if (r.ok) {
    // r.target 就是数据地址
} else {
    // r.matches == 0  → 特征码失效（代码被改）
    // r.matches > 1   → 特征码不唯一（需要加长）
}

// 更底层：拿到命中位置自己解析
auto hits = scan::find_all(s, modBase, modSize, pattern, 8);
for (auto hit : hits) {
    uintptr_t data = scan::resolve_rip_relative(s, hit, 3, 4);
}
```

## 怎么挖特征码

扫描器有了，特征码从哪来？三条路：

### 1. 抄现成的

很多游戏的公开项目里已经存了成批特征码。搜索方式：

```
github search: "<game> dumper" / "<game> offset" / "<game> sdk"
```

抄过来后在**你自己的版本**上验证——版本不同，特征码可能失效或不唯一。

### 2. 从反汇编里挖

用 IDA / Ghidra / REA 打开 exe：

```
1. 找关键函数（搜字符串、搜导入函数调用、从已知 API 反推）
2. 看它访问哪个全局变量
3. 那条指令就是特征码的种子
4. 取它前后 10~20 字节，把会变的部分（disp、立即数）替换成 ??
5. 全模块扫一遍验证唯一性
```

### 3. 从已知偏移反推

如果已经用人工方式找到一个偏移：

```
1. 在反汇编里对该地址做 xref（找谁引用了它）
2. 找到引用指令
3. 取指令周围的字节做特征码
4. 验证：扫出来的地址 == 已知偏移
```

这是最稳的验证方式——**先用已知答案验证扫描器正确，再用它找其他未知的**。

## 特征码设计要求

| 要求 | 说明 |
|---|---|
| **唯一** | 全模块只能命中 1 次。命中多个说明太短，要加长 |
| **稳定** | 不要包含立即数、字符串常量、跳转目标——这些容易变 |
| **够短** | 越短扫描越快，但太短会不唯一。10~30 字节是常见区间 |
| **通配恰当** | disp/imm 必须通配；操作码和寄存器字节保持固定 |

反面例子：

```
❌ "48 8B 05 ?? ?? ?? ??"            ← 太短，通常命中几十处
❌ "E8 ?? ?? ?? ?? 48 8B 05 ..."     ← 以 call 开头，目标地址会变
✅ "48 8B 05 ?? ?? ?? ?? 33 DB 45 8B E1"  ← 7 字节模式 + 4 字节固定尾部
```

## 已知限制

| 限制 | 说明 |
|---|---|
| 只能找**静态**地址 | 堆上的对象不能用特征码定位，只能通过指针链追溯到静态根 |
| 需要代码段可读 | 极少数加壳/自解压程序会边运行边解密代码，静态扫描可能失效 |
| 特征码需要**逐版本**维护 | 代码大改（比如换编译器、大重构）时全部失效 |
| 无法定位**对象内偏移** | 特征码找的是"对象在哪"，不是"对象里第 0x2C0 字节是什么"。后者仍需结构分析 |

最后一条最容易被误解：**特征码能替代"找静态基址"这一步，不能替代"分析结构体布局"**。

## 测试覆盖

42 项断言（`test_pattern_parse` / `test_scan_live` / `test_resolve` / `test_rip_relative`）：

- 三种写法解析一致
- 通配计数正确（`??` = 1 字节）
- 全通配被拒绝（必须有固定字节）
- 非十六进制被拒绝
- MZ / PE 签名定位准确
- 全模块扫描能找到 rip 相对寻址指令
- disp 解析出的地址可读
- **不唯一模式被拒绝**
- 不存在的模式返回失败
